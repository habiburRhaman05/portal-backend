# BDCap Client Portal — Handoff

## Architecture

```
Browser (portal HTML at /clients/portal/)
   │  POST /api/portal/save (debounced ~2s)
   │  POST /api/portal/submit (on Confirm submission)
   │  POST /api/portal/change-request (when locked)
   ▼
Our backend (Express on Vercel)
   │  Session → contact email (never from body/URL)
   │  Strips forbidden fields, enforces lock
   │  Forwards to GHL inbound webhook
   │  Also writes directly to GHL API
   ▼
GHL (contacts, custom fields, workflows)
   │  Inbound webhook → Create/Update Contact + Note
   │  Locked On set → Outbound webhook → Generator
   ▼
Generator host (Python 3 + Playwright)
   │  generate.py → 3-page site + build report
   ▼
Staging → CSM approval → Client sign-off → Live domain
```

## Environment variables
See `.env.example` — every variable is documented there. Critical:
- `SUPABASE_*` — auth
- `GHL_*` — GHL API and webhooks
- `SESSION_SECRET` — 64+ chars, random
- `PORTAL_ORIGIN` / `SITE_ORIGIN` — CORS origins

## Security invariants
1. Identity from server session only — never URL, body, or headers
2. Forbidden fields always stripped: `lockedOn`, `changesUntil`, `completedOn`, `clientNumber`, `sitePreviewUrl`, `siteDeployedOn`, `siteUrl`, `contactFirstName`, `contactLastName`
3. Locked portal refuses writes (HTTP 423)
4. Rate limiting on auth (20/15min) and portal routes (30/min)
5. CORS locked to configured origins
6. No PII in logs

## What is manual
- GHL workflows (inbound webhook, change request, scheduled lock, outbound lock)
- DNS records (clients CNAME, www CNAME for client sites)
- GHL code site creation and file upload (publish)
- Client Number assignment
- SharePoint folder creation
- Phone number update + site regeneration

## Known limits
- Generator runs one job at a time
- Session lifetime is 1 hour (Supabase token)
- First-visit account creation does not yet verify the email exists as a GHL contact (needs GHL token)
- No GHL code site API available — publish is manual
- `ghlWidgetId` source not confirmed
